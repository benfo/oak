# Roadmap

## Project goals
- Build a modern, simple Git client that feels dependable and a pleasure to use. Consistency and user joy are product goals, alongside correctness.
- Keep keyboard, mouse, focus, selection and feedback predictable across views. Optional navigation schemes add keys, not different rules for search or actions.
- Make frequent workflows quick without clutter. Add contextual controls and commands only when they solve a demonstrated need; preserve position and selection, avoid layout shifts, and make state visible.
- Evaluate changes by reduced confusion, fewer unnecessary steps and the user's local testing, rather than feature count.

### Conflict handling, first milestones (2026-10-22, tested, shipped in 0.1.13)
- Principle: no built-in resolution editor. Oak relies on Git and the user's merge tool (Preferences > Git), like GitExtensions, and stays simple so it can grow. A first attempt with ours/theirs branch labels, a dropped-changes confirm, an Undo toast and Skip was reverted as too much; those ideas are in the Backlog.
- Auto-switch to Changes when conflicts appear (`RepoView.tsx`). The "Stopped with conflicts" error toast was removed (`reportOpError` ignores messages matching /conflict/i) because the switch and the banner already explain it.
- Open in merge tool (`handlers.ts` `openMergeTool`): runs `git mergetool --no-prompt` with `mergetool.keepBackup=false`, `keepTemporaries=false` and `writeToTemp=true`, so BASE/LOCAL/REMOTE live in the system temp folder. Entry points: the operation banner (all conflicted files, one after another), a git-merge icon on each conflicted row, the row context menu. With no tool set, a toast offers Open Git settings. Git's own mergetool stages the file when the tool exits cleanly.
- Refreshes from the file watcher and window focus are paused while any operation is busy (`useRepo.ts` `busyRef`); one refresh runs when it finishes. This hides the brief backup files the merge tool creates in the working tree.
- Enter / double-click on a conflicted file no longer resolves it: it shows a short hint (accidental key presses must not decide a conflict, and opening the merge tool can be slow). Mark as resolved (row button, menu, palette) first checks the file for `<<<<<<<` and `>>>>>>>` lines (`handlers.ts` `conflictMarkers`) and asks for confirmation if any remain. Ours/theirs skip the check.
- VS Code's "Git repository found in parent folders" prompt appears when it opens the merged file. It comes from VS Code, not Oak; set `git.openRepositoryInParentFolders` to `never` or click Never.
- Test repos: `make-conflict-repos.ps1` builds merge, rebase, cherry-pick, revert, stash-pop, delete-modify and clean repos in `%TEMP%\oak-conflicts` (kept in the session files folder, not committed).
- Not done: stash-pop conflict banner (no banner when Git state is clean), labels that say which side "ours" and "theirs" are (swapped in a rebase), modify/delete conflicts (`git mergetool` asks a terminal question Oak cannot answer, so use ours/theirs), pulling conflicts into the same flow from Pull/Rebase, and Skip.

- Also: History working-changes file picks reuse the working file list within one status refresh (`createCommitPreviewLoader` `revision` argument), so they run only the file's diff instead of three git processes. Remaining latency is git's per-process startup (about 200 ms measured here); a diff cache plus neighbour prefetch is an unbuilt idea.
- Helpers `singleLane` and `splitFileLogChunk` live in `src/shared/fileLog.ts` (tests in `tests/file-log.test.ts`); `useRepo.ts` `fileFor(range)` encodes that a comparison wins over a file filter.
- Lean file-history previews (agreed in grilling, 2026-10-20): while stepping through a file's history, `createCommitPreviewLoader` takes the selected `Commit` (`fileCommit` argument) and runs only the file's `git diff`; the header (author, date, subject) comes from the graph data, so there is no `git show`, `diff-tree` listing or numstat, and no full message body. `splitFileLogChunk` also returns `status` and `oldPath`, so rename commits diff as real edits. Leaving file history (Escape) returns to the normal graph where the full file list loads. `CommitDetails` includes the lean flag, status and old path in its load key so starting or ending file history reloads the preview.
- `useRepo.ts` `commitsFile` is the file `commits` was listed for and lags `historyFile` while `git log --follow` runs. The graph draws a single lane only for a list that is a file's history, and `HistoryView` dims the stale list (`CommitList` `loading`) and shows a status after 300 ms instead of briefly drawing the old list as a single lane.
- Unbuilt: neighbour diff prefetch if stepping is still not snappy; a state management library (for example Zustand) for the selection and history-scope state shared by `HistoryView`, `CommitDetails` and `useRepo`, to be reconsidered after more testing.
- Per-file history is a filter on the History graph (`historyFile` in `useRepo.ts`, `git log --follow --name-status`, single-lane graph, "History of <path>" banner with Show all commits). Entry: "Show file history" in file context menus (Changes, History commit files, All files tree) and palette "Show file history…". It stacks on the branch scope, ends any comparison, preselects the file at each commit's path (renames followed), and clears on launch, repo switch, comparison, the banner button, sidebar commit focus and Escape in the graph. Blame is the next milestone.

### Copy and text selection in diffs (2026-10-19, tested, shipped in 0.1.10)
- Root cause of "Ctrl+C pastes nothing": the app menu is null on Windows/Linux, so Chromium has no Copy accelerator for non-editable text. Copy is now a command in the shortcut dispatcher (`App.tsx` `copy`, `lib/copy.ts`): Ctrl+C copies the window's text selection if any (any selectable area), else the focused diff's picked lines or cursor line as plain code (no +/- or line numbers). Ctrl+Shift+C with a diff focused copies those lines as a patch (hunk headers and prefixes); elsewhere it still copies the commit hash (`Command.when`). Right-click / Shift+F10 in a diff offers both; every copy shows a toast. Pure builders in `lib/diffCopy.ts` (`tests/diff-copy.test.ts`).
- Text selection is native: drag, double-click word, triple-click line. Picking lines clears an older text selection. In side-by-side a drag stays within its column. Highlight uses the new `--text-selection` token via `::selection`. Blank lines now survive a native copy. No caret mode or Vim visual mode by design; keyboard selection stays line-level.
- Test: `npm run dev`, drag over code in a diff, Ctrl+C and paste; Shift+↓ lines then Ctrl+C and Ctrl+Shift+C; right-click a diff line; side-by-side drag across the divider. Real mouse drags verified through the new dev helper `Drag@x1:y1:x2:y2` (`OAK_SCREENSHOT_KEYS`). Side-by-side selection was broken before: the column's focus redirect fired during mousedown and cancelled the selection, so it is now deferred.
