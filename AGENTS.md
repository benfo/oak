# Oak

Git GUI: Electron + React 19 + TypeScript (electron-vite). Runs the user's installed `git` CLI, never a Git library, so hooks, credentials, config and LFS match the command line. Windows 11 primary, Linux experimental, macOS untested (say so honestly in docs).

At session start, read `AGENTS.local.md` (repo root, gitignored, per-clone maintainer workflow rules) if it exists. Its rules apply to all work.

Principles are in [PRODUCT.md](PRODUCT.md), the visual system in [DESIGN.md](DESIGN.md), status and decisions in `ROADMAP.md` (keep it current when work ships or ideas are agreed). In short: everyday Git done simply, the same action behaving the same everywhere, Fetch/Pull/Push stay on the toolbar, no new permanent UI or commands without a concrete workflow benefit.

## Commands

- `npm run dev` (restart for main-process changes), `build`, `typecheck`, `lint`, `format` (`format:check` in CI), `npm test`. Run typecheck, lint, format and tests before proposing a change.
- `npm test`: `tests/**/*.test.ts`, Node runner, real git in a temp repo. Node-tested modules import siblings with `.ts` extensions.
- `npm run test:ui`: builds, then drives the real Electron app with Playwright (`tests-ui/`, serial, real repos and keystrokes). Not in CI yet. Run after changing views, diff or keyboard code. Each test launches a fresh app (about 2 s; about a minute in all), so run only what you touched (`npm run test:ui -- -g "name"`) and keep the full run and `--repeat-each` for the end. Stops at first failure, 5 s assertion timeout. Wait for a view switch to settle (destination focus) before the next shortcut, make one `page.mouse.move` before the first hover (the first move after launch only wakes hover up), scope locators when labels repeat, and confirm a bug-fix test fails without the fix.
- `npm run perf:open -- <label> <runs> <repo>...` (after `npm run build`): launches the real app per repo and prints median open timings and git command counts (`scripts/perf-open.cjs`). Compare commits by running it on each with another label.
- `npm run dist` (Windows installer), `dist:linux`, `icon` (renders `build/icon.png` from `build/icon.svg`).
- Releases are the maintainer's job (`docs/releasing.md`): never run `npm run release`, push `vX.Y.Z` tags or trigger website publication.
- `npm run site:dev|check|build` work on `website/` (Astro, Tailwind, daisyUI; `npm ci --prefix website`). Factual copy, synthetic screenshots, no sales language or unsupported superiority claims. Section backgrounds alternate strictly: adding or removing a section re-flips the rest.
- **Branches:** never commit to `main`. Branch from up-to-date `main` before the first commit as `feature/`, `fix/`, `docs/`, `chore/` or `website/` plus a slug. Land by PR (squash only). Do not push, merge or tag unless asked (`CONTRIBUTING.md`). Docs belonging to a change go in its branch; `docs/` is for standalone docs.
- Dev helper (after `npm run build`): env vars `OAK_SCREENSHOT=<png>`, `OAK_SCREENSHOT_DELAY`, `OAK_SCREENSHOT_KEYS` (real keys and clicks), `OAK_SCREENSHOT_JS` in `src/main/index.ts`. Verify UI by driving the app, not guessing.
- Dev builds only (never packaged): F12 toggles developer tools; Shift+F12 simulates Windows high contrast (`src/main/devForcedColours.ts`). Playwright key presses never reach these main-process keys, so tests send them with `webContents.sendInputEvent`.

## Architecture

- Refreshes set only changed state (JSON compare) so selections stay stable. IPC is `git:<name>`; `STREAMING` ops stream long output (`outputSink`). Renderer calls go through the typed proxy `api.<handler>()`.
- **Layout:** feature folders (`diff/`, `history/`, `changes/`, `sidebar/`, `blame/`) hold their components, hooks and helpers; shared UI in `components/`, logic in `lib/`, pure code shared with main in `src/shared`. Split a file that does more than one thing (ESLint `max-lines` 300 is a prompt to look).
- **File icons** (`settings.fileIcons`: `none` default, `simple`, `material` shown as "Colour"): packs are pure data (names, prefixes, extensions with longest compound extension winning, optional light variants). Add an icon by vendoring its SVG and mapping it in `materialPack.ts` (`tests/file-icons.test.ts` checks it exists). Icons keep a fixed slot and recede at rest.
- **Remote links, previews:** `shared/remote/rules.ts` takes injected git facts so it is unit tested without git and never offers a 404. A previewer is a view (`SideBySidePreview`, `PreviewSide`) listed in the registry; `DiffView` knows no formats; render untrusted formats through `<img>` only.
- Long lists use `@tanstack/react-virtual`. Graph and diff are custom; everything else interactive is React Aria Components themed with `data-*` attributes. Shiki highlights in a Web Worker with `--syntax-*` tokens.
- Menus must not wait on git: cache slow data (remote default branch) and refresh in the background.

## Design rules

- **One scroller per axis.** A pane never scrolls (`.split-pane` clips); only the region inside does. A header beside a scrolling body follows it. `tests-ui/no-stacked-scrollbars.test.ts` enforces it: extend its views when adding one.
- **Responsive, not hardcoded.** No guessed toolbar heights, reserved widths or breakpoints. Toolbars wrap and columns drop as space shrinks. Pane minimums live in `lib/layoutMinimums.ts`; saved sizes are preferences that return when there is room; `Split` enforces them.
- **No layout shift.** Transient UI (status, progress, selection bars, hints) uses reserved space or overlays and never moves content under the mouse. Delay progress UI about 300 ms. Keep button widths stable while busy.
- **Tokens only.** No raw colours, spacing, radii, font sizes or control heights; use `src/renderer/src/tokens.css` (`--space-*` 4px, `--radius-*`, `--text-*`, `--control-*`, `--row-*`, semantic colours paired with `-foreground`). Add a token deliberately if none fits; `npm run lint` enforces it.
- **Feature CSS:** one plain file per feature in `src/renderer/src/styles/`, imported from `styles/index.css`. New features get their own file imported last. Import order is the cascade: do not reorder.
- **One focus system** (`styles/focus.css`): controls get a 2px `--focus-ring` outline; panes sit in `.pane-frame`, which draws the ring only for keyboard focus (`lib/focusRing.ts`); rows use a tint and accent bar, never a ring hugging text. New scrolling panes go inside a `.pane-frame`.
- **Rows:** `--row-pad` on both sides, nesting adds `--indent`, keep `ROW_H` constants in sync with `--row-md`.
- Disabled buttons look inert and visible text says why (no tooltips on them). Ctrl+A is scoped to the focused pane.
- **Menus:** big lists are searchable pickers anchored to their toolbar button; small action and right-click menus are React Aria menus (`showMenu`, `ContextMenu.tsx`), at the pointer for right-click and under the focused row from the keyboard. One level of submenus, rare variants only. Group order, divided: do, explore (Compare, history, blame), go elsewhere (local first: "Open in editor", "Open with default app" for non-text files, "Show in Explorer"; then flat "Open in browser", "Open pull request"), Copy submenu, destructive last (Manage, Undo, Discard). No icons.
- **Pickers preview live:** moving onto a choice previews it, Enter keeps, Escape reverts; never dim the app.
- **Dialogs are keyboard-first:** initial focus on something arrows can drive. A dialog opening another closes synchronously (`flushSync`) and refocuses its opener first.
- **Explicit diff selection:** a click selects exactly the displayed line; Ctrl-click or Space toggles. Never infer replacement pairs or moved lines, and never let alignment or word highlighting expand a selection. Partial operations keep line order and leave unselected changes untouched.
- **Reuse before building.** Do not copy a feature into a second view. View-independent logic goes in `src/shared` as pure, unit-tested helpers; view-independent UI in a shared component plus hook; each view supplies only its text, line model and cursor. Reconcile with existing conventions rather than building a parallel one.
- **Colour and contrast.** Syntax tokens carry inline colours that beat stylesheets, so never pair a solid fill with contrasting text over code. Mark matches and selections with translucent tint tokens (both themes) and a ring. Check light and dark. Windows high contrast (`forced-colors`) drops tints, shadows and coloured backgrounds, so anything shown only that way needs a forced-colors rule (selection rings live in `styles/focus.css`); check with Shift+F12 in dev and extend `tests-ui/high-contrast.test.ts`.
- **Show the user's unit.** Counts say what a person sees (find counts occurrences, not lines). A hint for a key that does nothing reads as a bug: say why in reserved space, never a corner toast about the cursor line.
- **Reloads keep the screen.** A setting that reloads the same file keeps old rows until new ones arrive; show loading only when the file or revision changes. After a content-changing step, restore the cursor row.
- **Mouse matches keyboard.** Every widget key gets a visible button (key in its tooltip); every button action is reachable by key.
- **Say what happened with `notify`,** never which surface: errors, warnings and anything with buttons are toasts (bottom-right, `--toast` tone, icon for errors and warnings); results and hints are the status bar's line (about 4 s); a running operation is the bar's progress after 300 ms, so give `withBusy` a `done` text instead of toasting after it. Status items are actions (hover tint, a hover card, the same command as everywhere) or plain facts, never Tab stops, and every action has a key. A form's own failure stays beside the form (the commit box).
- **Accurate feedback:** refresh the working diff after content changes even when status codes match. A successful operation never looks like nothing happened.

## Keyboard model

- **Ownership:** text fields own text editing; the focused widget owns moving and selecting within itself; commands (changing app, repo or layout) belong to the shortcut dispatcher, which sees only keys no widget consumed.
- **Widget keys are data** in `lib/keymap.ts` (`WIDGET_KEYMAP`: action to keys per role `list`/`graph`/`diff`/`blame`, optional `help`). Components call `widgetAction(...)` or `lib/navigation.ts` helpers; never test `ctrlKey`/`altKey`/`key` in a component. A new widget key needs a `WIDGET_KEYMAP` entry and a test in `tests/shortcuts-keymap.test.ts`.
- **Shortcuts:** `lib/shortcuts.ts` is the only dispatcher (`useShortcutRoot` in `App.tsx`). Register via `useShortcutScope` and `commandBinding`; overlays call `useShortcutOverlay`. Never add `window` keydown listeners. A disabled binding keeps its key and toasts its `disabledReason`. Global commands live in `RepoView.buildCommands`; Ctrl+/ is the cheat sheet.
- **Shared policy** in `lib/navigation.ts` (via `lib/useNavigation.ts`, capture phase, before React Aria): `handleNavigation(event, { activate, deeper, back, dismiss, discard, menu })`, omitting what does not apply. New areas pick a role (collection, persistent find, choice picker, native form) and reuse its handler; never apply Vim aliases in forms or dialogs.
- **Panes:** Changes, History and the sidebar use `lib/usePane.ts` and `components/Pane.tsx`. Tools and forms declare `data-pane-owner`; persistent search uses `data-search-pane`.
- **Search is explicit:** `/` or Ctrl+F searches the focused list; typing never starts search. Persistent search keeps focus while Enter/Shift+Enter step, Escape returns to the owning list keeping the query, and it is not a Tab stop. Choice pickers: Enter accepts, Escape cancels. File pickers select the found row and never stage or open the diff.
- **Focus after a button press:** keyboard presses leave focus on the button so Enter repeats; only mouse or touch (`pointerType`) hands focus back to the field or code. Ignore `event.repeat` on history-stepping keys.
- **Escape** closes the topmost transient layer (menu, popover, find bar, line selection), then restores expanded Code when nothing remains. It never navigates between content panes or leaves a view. A visibly announced temporary mode with an Exit control may use Escape only within its owning context after overlays close, and every exception is agreed explicitly. Agreed: comparison and file history exit from the graph (including empty results) or banner/controls, never from code or file lists; repeated Escape in a diff preserves them. Pane tools return focus to their pane. Use `handleDismissNavigation`; key repeat cannot dismiss successive layers.
- **Tab and F6:** Tab is native/React Aria traversal (one stop per collection; fixed pane tools in DOM order; per-item buttons and search fields excluded). F6/Shift+F6 are the only pane jumps.
- **Lists:** arrows, Home, End, PgUp, PgDn move; Space selects; Enter acts; Delete discards; Shift+F10 or Menu opens the context menu; Right goes deeper (graph, commit files, diff), Left back. Switching panes preserves selection. Alt+Left and Alt+Right are Back and Forward through places visited (not in text fields); `lib/navigation.ts` (`isHistoryChord`) passes them out of list rows to the dispatcher.
- **Diff:** line cursor; Shift+arrows, Space, Ctrl+A select; Enter stage/unstage; Delete discard; N/P hunks; Shift+Left/Right scroll sideways without moving focus, cursor or selection; Escape closes find, then clears selection, keeping focus in the code. Ctrl+Shift+D toggles Inline/Side by side through `changeDiffLayout.ts` only (keeps anchor, focus and selection).
- **Vim keys** optional, off by default: h/j/k/l, Ctrl+D/U, gg/G in lists and diffs via `useNavigation`; menus h/j/k/l only, and once you have typed a letter in a menu the following letters stay type-ahead for a second ("ch", "squash"); no editing modes.
- **History All files** is a tree: arrows move, expand and collapse only; Enter opens a file.
- **Layouts:** F11 and the toolbar button expand the code area (sidebar, icon rail and History graph go; the file list stays beside the diff). `F` toggles that list (session only). `Ctrl+[` or the pane toggle collapses the sidebar to an icon rail (`sidebarHidden`, persisted; no-op in focus mode). Code is the only expanded layout; Escape restores it only when no widget has anything to undo (dispatcher fallback). Hidden panes stay mounted but inert, skipped by F6/Tab. No docking, saved layouts or automatic collapsing.
- **Splits:** `Split.tsx` wraps `react-resizable-panels`; keep pixel-size preservation, `split:<id>` localStorage keys and a descriptive `label`. Shift+Alt+arrows move the nearest divider (`lib/paneResize.ts`). Dividers are not Tab stops.

## React Aria lessons

- Extra keys (Right, Delete, Shift+F10): capture-phase handler on a wrapper, before React Aria.
- Items have no `onFocus`: listen on a wrapper and read `[role=row]`'s `data-key`.
- Pass React Aria's `Selection` back unchanged (carries the Shift+click anchor); build your own with the same class (`anchored()` in `ChangesView`). Cached item elements need `dependencies` or a ref, or handlers go stale.
- Virtualized rows sit in sized wrappers: `[role=row]` and its gridcell `height: 100%`, spacing inside the row.
- RAC `Button` drops `title`: use a native `<button>` or `Tip`.
- Big collections: the sidebar Tree rebuilds its collection every render, so omit collapsed sections' children (handle Right/Left yourself), cache row elements per data object, memoize the whole `<Tree>`, drive cheap visuals from context. Palettes use a virtualized `ListBox`, lowercase text once per picker and `useDeferredValue(query)`.
